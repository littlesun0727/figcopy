# 相框内窗色键规则：真实生图对照结果

## 结论

本次试验支持增加相框内窗色键要求：两张白色相框在原 prompt 下均生成不透明内窗，新增规则后均生成绿色内窗，并由已有去底代码处理为透明。流星和播放器两组没有观察到被误当作相框挖空。

左上相框的新结果同时画入日文 caption、笑脸与蓝色装饰；这些内容在 test2 中已有独立图层，直接替换会导致内容重复。原 prompt 的这次输出没有这些内容。由于每组仅一次、没有固定随机种子，不能把此差异确定归因于新增规则，也不能据此宣称对所有其他素材无影响。

## 试验控制

- 模型：doubao-seedream-5-0-260128，2K，沿用原 Yibu 审计通道。
- 四份原参考裁片，两种 prompt，共 8 次真实生图；VLM 调用 0。
- 新旧组的图片、模型、参数、原制作要求相同，只在生图 prompt 中插入下方规则。
- 使用隔离缓存；8 个结果均为新请求，fixture=false、cache_hit=false。
- 复用现有 `_build_overlay` 去色键和主体裁边；没有增加本地挖窗、窗口检测、重生成或几何修复。
- 原 test2 模板哈希在试验前后相同；生产代码和原素材未被本试验替换。

## 逐件观察

| 素材 | 原 prompt | 新增规则 | 说明 |
|---|---|---|---|
| 左上白色拍立得 | 内窗白色、不透明 | 内窗绿色，去底后透明 | 框体、纸纹保留；额外画入日文和装饰，存在重复叠加风险 |
| 右下白色相框 | 内窗白色、不透明 | 内窗绿色，去底后透明 | 框体、纸纹、底部宽边保留 |
| 流星贴纸 | 主体和填色正常 | 主体和填色保留 | 未见误挖空；形状、位置存在生成差异 |
| 音乐播放器 | 粉色底板、时间与图标正常 | 粉色底板、0:30/3:20 及图标保留 | 未被误认为照片相框；尺寸和笔画略有变化 |

两张白框均从中心区域 alpha=255 变成 alpha=0。素材宽高各 35%–65% 的中心检测区，透明像素比例从 0% 变成 100%。这个中心指标本身不代表边缘质量或全图布局通过，透明内窗还通过原始输出和去底对照图作了目视核对。

## 实际新增规则

> 如果本素材是相框、拍立得或胶片边框，照片窗口内部必须填充与外部背景完全相同的纯色色键 {key_hex}。窗口内不得出现照片、白色或灰色底板、渐变、纹理、阴影或透明棋盘格。相框纸边、底部宽边及其装饰保留原有颜色和质感。照片窗口与外部背景均供程序后续去底。

本次四份裁片选择的色键均为 #00FF00。

## 建议与边界

内窗色键要求可以作为轻量改进候选。若进一步修改文字，建议收窄为只约束照片开口，不额外强调保留框上的装饰；这属于根据本次观察提出的后续建议，缩短版本尚未试跑。

此次试验没有修复相框尺寸、照片对齐和素材归属，也没有进行完整 pipeline 重跑。两种非相框的结果只能支持“本次未观察到误挖空”，不能当作所有装饰类型都不受影响的保证。
