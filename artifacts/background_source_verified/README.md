## 实际测试

环境：Windows，`env_py11`，Python 3.11.16、PyAV 18.1.0、pytest 9.1.1；浏览器为本机 Edge。

最终全量：**276 passed in 34.48s**，其中 7 项是真实浏览器测试（4 项背景来源、3 项原保存规则）。12 个涉及的 Python 文件通过 Ruff 检查及格式检查，`git diff --check` 通过。

执行形式如下。实际运行使用独立、此前不存在的临时目录；不要把已有用户数据目录传给 pytest 的 `--basetemp`。

```powershell
# 在 env_py11 中执行；tmp 路径每轮唯一。
$figcopyBackgroundTestTemp = Join-Path ([System.IO.Path]::GetTempPath()) ('fbg-final-' + [guid]::NewGuid().ToString('N'))
python -B -X utf8 -m pytest -q -p no:cacheprovider --tb=short --show-capture=no --basetemp $figcopyBackgroundTestTemp
```

## 过程中的真实问题与处理

- 初始 base Python 缺少 PyAV：第一轮 80 项通过、1 项因缺依赖失败。随后在用户实际使用且已具备 PyAV 的 `env_py11` 中安装 pytest、websocket-client 和 Ruff；相关旧回归 81 项通过。
- 新增用例暴露了恢复稿缺少 source 尺寸、旧默认 shape 覆盖当前编辑的情况，均已修复。新增 20 项用例及 7 项浏览器测试随后通过。
- 第一轮全量结果为 270 项通过；补充复制失败、资源独立性和前景混合模式等用例后，最终为 276 项通过。
- 缓存重建测试曾因 pytest 临时路径叠加长测试名超过 Windows 路径限制失败；该合成测试改用短子目录，不修改用户数据路径，也不改生产缓存协议。
- 最终检查前有两次用户中断；没有把未取得完成结果的运行算作通过。恢复后确认无对应遗留 pytest 进程，再运行独立的最终全量测试。

## 边界与使用

所有新增图片、模型返回和生成行为均为合成 fixture 或模拟 provider。浏览器运行的是真实界面，但未向任何真实模型发请求。没有改动迁移数据、没有代替用户确认 S02，也没有宣称真实街景图视觉验收通过。

更新后重启工作台并刷新浏览器。在原项目的“项目文件”区域点击“修改背景来源，另存版本”；在新审核页选择背景照片槽，检查后整体确认。S02 使用现有 `slot_bg_photo`。装饰若仍需模型生成，凭据错误仍要单独解决。

此记录仅证明本轮程序行为与兼容回归，不证明 VLM 总能判断正确，也不保证所有未测试的新素材都满足覆盖和视觉要求。
